# TerraEyes Architecture Document

## System Overview
TerraEyes is an analyst-oriented geospatial intelligence platform operating entirely offline after deployment. It supports multi-sensor satellite imagery ingestion, natural language & visual semantic retrieval, bi-temporal change detection, and structured reporting.

## Storage Architecture
1. **Relational & Spatial Store (SQLite)**: Stores tile metadata, geographic bounding boxes, resolution, timestamps, and sensor provenance.
2. **Vector Index (FAISS)**: Offline inner-product / cosine similarity index for global vision-language embeddings.
3. **Temporal State Store (HDF5 / Persistent)**: Stores recurrent Mamba state space representations across acquisition dates.
4. **Mask Cache**: Stores binary change masks generated by the detection service.

## Implemented Temporal Change Model

The optional `mamba_cd` backend uses a shared spatial CNN encoder, bidirectional
horizontal/vertical selective state-space scans, a temporal selective scan, and
a binary change decoder. It accepts an
ordered sequence of co-registered RGB acquisitions; inference over a tile's
known dates processes intermediate dates as well as the selected endpoints.
Per-date SSM state, causal-convolution context, spatial features, and temporal
features are stored in the configured HDF5 file and reused when later dates are
processed. A checkpoint fingerprint prevents state generated by a different
model from being reused.

This is a small PyTorch reference implementation of the Mamba selective
recurrence, not the official fused `mamba-ssm` CUDA implementation. The OSCD
training/evaluation path supervises binary change masks. OSCD does not provide
the land-cover transition labels required to train or score semantic classes
such as demolition, road construction, or vegetation loss. The production
default remains Otsu until a clean external holdout justifies changing it.
